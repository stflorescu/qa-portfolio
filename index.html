Selected work

  1. Case 01

    Calling a NO-GO

    NO-GOSpec-based testing · edge cases · release decisions
    Problem
    A new slot game's optional "extra play" cost 1.5× the stake, and the spec called it fine.
    What I did
    Turned the spec into ~90 checks and played the edges of the play limits. At the maximum stake the real cost broke the platform limit, and I re-tested in a fresh session before reporting.
    Result
    A clear NO-GO with evidence, so the launch decision was made knowingly.
  2. Case 02

    Proving games pay what the rules say

    Game maths · statistics · Node.js
    Problem
    The server calculates every win; I wanted a check that did not depend on the game's own code.
    What I did
    Wrote a verifier per game from the rules document (lines, wilds, cascades, bonus rounds, caps), plus statistical sanity checks (chi-square, z-score, Monte Carlo) on hit rates and RTP.
    Result
    4,000+ real rounds across 6 games, 0 maths mismatches.
  3. Case 03

    A QA tool for the whole team

    Chrome extensions · product thinking · Cloudflare Workers
    Problem
    Testers checked balances and banned wording by hand on every game.
    What I did
    Built a Chrome extension (Manifest V3 side panel): a round log, a balance check after each round, a banned-wording scan and a downloadable checklist, shipped with versioned releases.
    Result
    Reached v0.9.3; the QA team used it in their game testing.
  • Case 04

    Automation at platform scale

    ~350 tests; Plinko suite 26% faster, no new flakiness.

    Problem & approach
    Problem

    What I did

  • Case 05
